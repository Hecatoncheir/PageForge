# PageForge

[![CI](https://github.com/Hecatoncheir/PageForge/actions/workflows/ci.yml/badge.svg)](https://github.com/Hecatoncheir/PageForge/actions/workflows/ci.yml)

**Свой способ отображения для каждого сайта.**

[Сайт проекта](https://hecatoncheir.github.io/PageForge/)

PageForge — расширение для установки и переключения пользовательских вариантов оформления и структуры веб-страниц. Интерфейс написан на Flutter Web; небольшой JavaScript-слой работает с API браузера и применяет изменения к страницам.

## Текущее состояние

Первая рабочая версия использует интерфейс Flutter 380 × 580 в палитре Gruvbox, локальные Nunito, Nunito Sans и JetBrains Mono, логотип «Мастерская», светлую и тёмную темы.

Работают импорт ZIP выбором файла и перетаскиванием, карточки подходящих оформлений, применение CSS, собственная HTML-разметка с привязками к содержимому страницы, удаление, возврат исходного вида и выгрузка. Выбранное оформление сохраняется и применяется при следующих посещениях после выдачи доступа к конкретному сайту. Файлы и превью хранятся локально в IndexedDB.

Превью создаётся по видимой области открытого сайта: оформление временно применяется, затем восстанавливаются предыдущие стили и положение прокрутки. Браузер должен разрешить снимок текущей вкладки — обычно это происходит после открытия расширения его кнопкой. Если снимок недоступен или нужный сайт не открыт, карточка появляется с отложенным превью. При следующем открытии расширения на подходящем сайте выполняется повторная попытка.

Глубокая переделка зависит от устройства сайта. CSS сохраняет исходные элементы; режим HTML-шаблона поддерживает текст, очищенную разметку, ссылки, изображения и передачу нажатий исходным кнопкам. Он не воспроизводит произвольную логику приложения. Работа вложенных фреймов и закрытого Shadow DOM не заявляется. Разрешения, настоящий popup и создание снимков ещё требуют ручной проверки в Chrome и Firefox. Остальные этапы: [TODO.md](TODO.md).

[HTML/CSS/JS-прототип](design/Readme.md) и страница айдентики сохранены для локальной разработки. Публичный сайт показывает только статичный пример интерфейса.

## Как пользоваться

1. Открыть сайт и PageForge.
2. Во вкладке «Разработка» нажать «Выгрузить». Если выбран вариант, скачивается его пакет. Если ничего не выбрано — основа для нового варианта текущего сайта.
3. Распаковать ZIP и изменить оформление, разметку и правила привязки к содержимому сайта.
4. Перетащить новый ZIP в область «Добавить». Расширение проверит пакет и подготовит превью.
5. Выбрать карточку во вкладке «Отображение» и разрешить доступ к этому сайту, чтобы применить вариант и сохранить выбор.

У карточек есть кнопки «Удалить» и «Выгрузить». Список прокручивается и показывает варианты для текущего адреса. «Исходное отображение» возвращает исходный вид; удаление активного варианта также сбрасывает выбор.

ZIP получает имя домена текущего сайта, например `example.com.zip`, для выбранного оформления и для стартовой основы. При совпадении имени браузер добавляет номер к новому файлу.
В Chrome расширение повторно задаёт имя на этапе определения файла браузером. Сообщение после выгрузки показывает переданное имя архива.

В установленном расширении поверхность popup имеет квадратные края без дополнительной рамки. Скругление на 24 px сохранено только в локальном предпросмотре интерфейса.

Формат пакета оформления:

```text
my-appearance.zip
├── profile.json       # название, идентификатор, версия, подходящие адреса
├── styles.css         # оформление
├── layout.html        # необязательная разметка
├── rules.json         # привязки к элементам и разрешённые преобразования
├── assets/            # ресурсы варианта
└── reference/         # справочный снимок исходной страницы
```

ZIP оформления и ZIP самого расширения — разные форматы. [Описание формата и привязок](docs/appearance-format.md). Снимок страницы даёт основу для разработки, но не восстанавливает исходный проект сайта или его серверный код.

Два примера для `https://example.com/` находятся в [examples](examples): «Бумага» меняет CSS, «Новый взгляд» строит другую разметку на основе исходного текста и ссылки. Сборка добавляет соответствующие `pageforge-theme-*.zip` к пакетам. Готовых оформлений в новом хранилище нет — добавьте пример либо собственный ZIP.

## Установка

Пакеты появятся во вложениях [опубликованного релиза](https://github.com/Hecatoncheir/PageForge/releases). Для проверочных сборок их можно скачать из артефактов [GitHub Actions](https://github.com/Hecatoncheir/PageForge/actions).

| Браузер | Пакет | Установка для разработки |
| --- | --- | --- |
| Chrome | `pageforge-chrome-X.Y.Z.zip` | Распаковать, открыть `chrome://extensions`, включить режим разработчика, выбрать «Загрузить распакованное расширение» и папку с `manifest.json` |
| Edge | `pageforge-edge-X.Y.Z.zip` | Аналогично через `edge://extensions` |
| Firefox 140+ | `pageforge-firefox-X.Y.Z.zip` | Распаковать, открыть `about:debugging#/runtime/this-firefox`, выбрать «Загрузить временное дополнение» и `manifest.json` |

Firefox-пакет не подписан: временная установка действует до перезапуска браузера. Подписанный XPI и публикация в магазинах ещё не настроены. Пакет Chrome потенциально подходит другим Chromium-браузерам, но их совместимость отдельно не проверена. Safari потребует отдельного проекта и сборки на macOS; сейчас он не включён.

## Локальная разработка

Нужны Flutter **3.47.9** (версия также закреплена в [.flutter-version](.flutter-version)), Node.js 24 и Python 3.13. Python используется только для упаковки, Node.js — для проверки расширения.

```sh
flutter pub get --enforce-lockfile
npm ci
flutter analyze --fatal-infos
flutter test
python -m unittest discover -s tools -p "test_*.py" -v
python tools/build.py
npm run lint:firefox
npx playwright install chromium
npm run test:browser
```

Сборка создаёт распакованные расширения в `dist/chrome`, `dist/edge`, `dist/firefox`, а ZIP и `SHA256SUMS.txt` — в `release/`. Для установки локально выберите соответствующую папку `dist`.

Для отдельного предпросмотра интерфейса:

```sh
flutter run -d chrome
```

В обычной вкладке показывается подпись «Предпросмотр интерфейса». API расширения доступны только после загрузки собранного пакета в браузер. Отладочная сборка Flutter предназначена для обычной вкладки; в расширение упаковывается release-сборка с `--csp` и `--no-web-resources-cdn`.

## CI и релизы

`CI` запускается при изменениях в `main`, в pull request и вручную. Проверяет форматирование, статический анализ, Flutter-тесты, формат ZIP, упаковку и пакет Firefox. В Chromium проверяются загрузка Flutter, импорт файла, изменение CSS и разметки, откат после ошибки, сохранение после перезапуска, удаление опасных HTML-элементов при применении, выгрузка ресурсов и подготовка основы. Для тестового сайта доступ заранее выдан в проверочном манифесте; системное окно запроса разрешений и выдача `activeTab` остаются предметом ручной проверки. Проверка не заменяет приёмку в настоящем popup Chrome и Firefox.

При **публикации GitHub Release** процесс «Пакеты релиза»:

1. Берёт исходники именно из тега релиза.
2. Получает версию из тега и собирает Flutter Web с этой версией.
3. Повторяет проверки и создаёт отдельные манифесты: service worker для Chrome/Edge и background scripts для Firefox.
4. Прикрепляет три ZIP расширения, два ZIP с примерами оформления и `SHA256SUMS.txt` к опубликованному релизу.

Теги имеют вид `v1.2.3` или `1.2.3`. Каждая часть — от 0 до 65535, без ведущих нулей; `0.0.0` недопустима. Суффиксы наподобие `-beta.1` отклоняются. Для предварительного релиза используйте числовой тег и отметку Pre-release в GitHub. Версия в ZIP и манифестах определяется тегом; при обычной сборке — `pubspec.yaml`.

Для выпуска создайте и отправьте тег на нужный коммит, затем опубликуйте Release в GitHub. Само создание тега и сохранение черновика релиза не запускают выпуск. Публикуйте через интерфейс GitHub или личный токен: событие от другого workflow с `GITHUB_TOKEN` обычно не запускает следующий workflow.

Процесс можно запустить вручную с проверочной версией: он сохранит пакеты в артефакты, **не создавая релиз и не добавляя файлы к существующему**. Повторный запуск опубликованного релиза заменяет одноимённые вложения, поэтому неизменяемость релизов GitHub не должна быть включена для этой схемы. Дополнительные секреты для текущей сборки не нужны; право записи выдаётся только задаче прикрепления файлов.

Автоматическая отправка в Chrome Web Store, Edge Add-ons и Mozilla Add-ons не настроена. Это отдельный этап с учётными записями издателя и подписью Firefox.

## Устройство проекта

```text
lib/                  # Flutter: интерфейс, состояние, данные, связь с JS
web/                  # страница popup, локальная загрузка Flutter, JS-мост
extension/            # общий манифест, фоновые обработчики, значки
assets/fonts/         # локальные шрифты Roboto и их лицензия
test/                 # проверки интерфейса и состояния
tools/                # сборка, упаковка и проверка запуска
.github/              # CI, выпуск и обновления зависимостей
```

Расширение использует `activeTab`, `scripting`, `storage` и `downloads`. Постоянные разрешения запрашиваются только при выборе оформления для конкретного сайта. На серверы содержимое страниц не передаётся. CSS и ресурсы ZIP загружаются локально, `@import` не поддерживается. В справочной выгрузке удаляются сценарии, поля ввода и адресные параметры ссылок; сам текст страницы может содержать ваши данные, поэтому проверяйте архив перед передачей другим людям.

Workflow `Сайт` отдельно публикует главную страницу в GitHub Pages. HTML-прототип расширения и страница айдентики используются для локальной разработки и исключены из публикации. На главной размещена статичная иллюстрация; для работы с реальными сайтами требуется установленное расширение.

Mozilla linter выдаёт четыре известных предупреждения о динамическом `import` в сгенерированном коде Flutter. Проверка допускает только этот конкретный тип предупреждения в `flutter_bootstrap.js` и `main.dart.js`, отклоняя остальные предупреждения и все ошибки. Загрузка ресурсов ограничена локальными файлами через CSP, конфигурацию Flutter и проверку сетевых запросов при запуске. Успешная проверка не означает одобрения расширения магазином Mozilla.

Технические основания: [инициализация Flutter Web](https://docs.flutter.dev/platform-integration/web/initialization), [CSP расширений Chrome](https://developer.chrome.com/docs/extensions/reference/manifest/content-security-policy), [манифест Firefox](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/browser_specific_settings), [подпись Firefox](https://extensionworkshop.com/documentation/publish/signing-and-distribution-overview/).
