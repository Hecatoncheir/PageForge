# Формат оформления PageForge, версия 1

В корне ZIP обязательны `profile.json` и `styles.css`. Остальные файлы необязательны; для `mode: layout` нужен `layout.html`.

В версии разработки 0.2.0 те же файлы можно разместить в корне открытого репозитория GitHub и добавить ссылку во вкладке «Разработка». В отличие от ZIP, при импорте из репозитория берутся только файлы формата, ресурсы `assets/`, README и лицензия; `reference/` и служебные файлы игнорируются. Поддерживаются ветка по умолчанию, ссылки `/tree/ref` и `/commit/sha`. Повторный импорт с тем же `id` обновляет существующий вариант.

```json
{
  "schemaVersion": 1,
  "id": "my-paper",
  "name": "Моя бумага",
  "version": "1.0.0",
  "mode": "css",
  "matches": ["https://example.com/*"]
}
```

`id` — до 80 латинских букв, цифр, дефисов и подчёркиваний. Такой же `id` при импорте обновляет существующий вариант, новый — добавляет другой. `name` — до 80 символов. Версия записывается как три числовые части. Дополнительные поля метаданных сохраняются при выгрузке, но не управляют выполнением.

В `matches` допускаются от 1 до 20 правил: `https://example.com/*`, `*://*.example.com/articles/*`. Поддоменное правило также включает основной домен. Протокол `*` означает HTTP и HTTPS. Путь сопоставляется без параметров запроса; порт не включается в правило. Выбор пользователя хранится отдельно для каждого origin, включая фактический порт. Для одного origin активен один вариант; если его путь не подходит, страница остаётся исходной.

## CSS и ресурсы

Стили добавляются как пользовательская таблица CSS и удаляются при сбросе. Для надёжного переопределения авторских стилей можно использовать `!important`. Исходные элементы в режиме `css` не заменяются, поэтому их обработчики сохраняются.

```css
body { background: #fbf1c7 !important; color: #282828 !important; }
.illustration { background-image: url("assets/picture.webp"); }
@font-face { font-family: MyFont; src: url("assets/my-font.woff2"); }
```

Ресурсы должны находиться в `assets/`. Относительные `url(...)` в CSS заменяются локальными `data:`-адресами; разрешены также ссылки `#id`. Внешние URL и `@import` в CSS отклоняются. Используйте обычные, не экранированные пути файлов. Политика самого сайта может дополнительно ограничивать изображения и шрифты.

Файлы архива, включая дополнительные материалы в `reference/` и `assets/`, сохраняются при повторной выгрузке. Известные JSON-поля нормализуются. Файлы сценариев и другие исполняемые файлы не принимаются.

## Правила и собственная разметка

`rules.json`:

```json
{
  "hide": [".sidebar", ".banner"],
  "bindings": [
    { "source": "h1", "target": "#title", "kind": "text" },
    { "source": "article", "target": "#content", "kind": "html" },
    { "source": "a.read-more", "target": "#more", "kind": "href" },
    { "source": "img.hero", "target": "#image", "kind": "src" },
    { "source": "button.next", "target": "#next", "kind": "click" }
  ]
}
```

`hide` работает в обоих режимах и скрывает совпадающие элементы CSS-правилами. Привязки используются в режиме `layout`: первый `source` берётся из исходной страницы, `target` ищется в новом шаблоне. Доступно до 100 правил каждого вида.

```html
<main class="pageforge-layout">
  <h1 id="title"></h1>
  <article id="content"></article>
  <img id="image" alt="">
  <a id="more">Читать дальше</a>
  <button id="next">Далее</button>
</main>
```

Для включения шаблона установите `mode: "layout"`. Исходная страница продолжает работать, а её верхние блоки скрываются, пока существует `.pageforge-root`. Собственная разметка и скопированный HTML проходят очистку: сценарии, фреймы, формы, встроенные обработчики и неподдерживаемые элементы удаляются. Поведение задаётся только фиксированными типами привязок; код из архива не исполняется.

`click` передаёт нажатие существующему элементу. Некоторые сайты требуют настоящего пользовательского события либо зависят от видимости исходного интерфейса; универсальная совместимость таких действий не гарантируется. Для форм используйте CSS-режим или разрабатывайте отдельную совместимость сайта.

Изменения исходного DOM обновляют привязки. Новая разметка не получает копии обработчиков сайта. При сбросе удаляются добавленная таблица CSS и корень шаблона; исходные узлы не заменяются. Ошибка применения восстанавливает предыдущий вариант.

## Выгрузка основы

Если выбран вариант, выгружается он. При исходном отображении создаётся новый пакет с UUID, правилом текущего домена, начальным CSS, пустыми правилами, примером разметки и папкой `reference`:

- `page.html` — очищенная структура основного документа;
- `styles.css` — доступные через CSSOM правила, до 1 МБ;
- `computed.json` — основные вычисленные стили первых 200 элементов текста, ссылок и кнопок.

Сценарии, фреймы, формы и поля ввода в справочную разметку не включаются; адресные параметры ссылок удаляются. Загруженные с другого origin стили могут быть недоступны, изображения и серверный код целиком не копируются. Это справочный снимок, а не автономная копия приложения. Текст страницы сохраняется — учитывайте это при обмене архивами.

## Превью и ограничения

После импорта подходящего варианта расширение пробует временно применить его в активной вкладке, сделать снимок видимой области и восстановить предыдущий вариант и прокрутку. В это время может кратковременно измениться вид страницы. Превью хранится отдельно в локальной базе. Системное разрешение `activeTab` обычно выдаётся при нажатии кнопки расширения; без него снимок может откладываться до следующего открытия расширения на этом сайте.

Обрабатывается основной документ HTTP/HTTPS-страниц. Служебные страницы, магазины расширений и другие защищённые браузером адреса могут запрещать вмешательство. Вложенные фреймы и закрытый Shadow DOM не поддерживаются.

Лимиты: ZIP 8 МБ, распакованные файлы 16 МБ, до 128 записей, CSS 1 МБ, шаблон 512 КБ. До 50 оформлений и 64 МБ исходных файлов в локальной базе. Импорт становится устойчивым к закрытию popup после передачи архива фоновому обработчику и записи в базу; незавершённое превью повторяется при следующем запуске.
